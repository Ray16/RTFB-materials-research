# Recovering resource refusals before scientific launch

The [two retained cases](resolutions.json) were declined before a scientific
subprocess was created: a native state lost its free GPU, and an electronic
state found host RAM already promised. Their controllers were confirmed stopped,
no scientific outputs existed, and exact task-producer inventories were empty
on all nine policy-allowed nodes. Original claims, logs and placements remain
in runtime history. No scientific worker was signalled, and neither refusal
consumes a scientific attempt.

The source-bound classifier checks the exact traceback branch and verifies that
its unique literal refusal occurs before every subprocess creation in the
launcher. Changed source bytes, unknown messages, live/uncertain owners,
unreachable nodes, matching producers and any scientific output preserve the
claim. Both electronic and native queues now apply this recovery before their
normal state inspection; the shared GPU reservation and scientific numerical
checks remain unchanged.

Runtime recovery is recorded at
`results/validation/resource_refusals_2026-10-30/recovery.json`.
Current scheduling and physical-review outcomes remain at
`results/validation/native_conveyor_2026-10-30/dispatch/status.json` and
`results/validation/energy_classes_2026-10-30/queue/status.json`.
Reopening an unstarted task does not establish that it has since launched or
that an energy/free energy has passed physical review.
