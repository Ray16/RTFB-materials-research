# UMA Nitro installation and exact-state validation

The [installed environment](environment.json) uses FairChem commit `645af7d03e91138ef07e51de387316c9e2e152dc` (`2.24.1.dev4+g645af7d0`), Torch 2.13.0 and the official CUDA 13.0 index. All 126 installed distributions pass their dependency check. The [project specification](../../../environments/uma_nitro/pyproject.toml) and [uv lock](../../../environments/uma_nitro/uv.lock) retain the resolved stack. This separate prefix does not alter the frozen redox DFT environment.

**Actual Nitro inference is not yet qualified.** The [current status](summary.json) distinguishes installation from numerical and performance validation. The [frozen panel](panel/plan.json) contains ten exact-state cases and forty geometries: PMDI/NDI redox states, cationic viologen states, an open five-repeat two-graft PMDI input and a fixed-geometry triplet control. The polymer/spin inputs are method controls, not accepted minima or synthesis candidates. Model weights and atomic references are fingerprinted.

[Legacy inference](legacy_points.json) completed all ten cases on a reserved V100. All [six fingerprinted historical energies](legacy_energy_replay.json) reproduce, with maximum error 6.10e-7 eV. The four frames and repeated evaluations reset the ASE cache, and timing synchronizes CUDA. Legacy-only timing is not a Nitro speedup measurement.

The [strict Nitro adapter](../../../src/redox/qm/uma_nitro.py) requires an actual standalone Nitro executor before and after every evaluation and rejects changes in composition, task, charge or spin. A new calculator is required for a different state. [The qualification command](../../../scripts/validation/qualify_uma_nitro.py) retains exact input, code and checkpoint identities; [contract tests](contract_tests.xml) check explicit electronic states and fallback rejection. Current-release FP32 and actual Nitro evaluations, cross-mode energy/force review and matched-device timing remain pending. The default production pipeline is unchanged until those checks pass.

[The official inference documentation](https://facebookresearch.github.io/fairchem/ase-calculator/) requires NVIDIA capability 8.x-12.x for Nitro. V100/T4 devices fall back to other modes and cannot establish a Nitro test. Compatible H100 placement remains subject to the system reservation gate and actual residency checks. No occupied GPU is treated as available.

The environment, vendor source and raw outputs remain at `calcs/uma_nitro_validation/2026-10-23/` and `calcs/vendor/fairchem_nitro_645af7d/`. Source snapshots retain the exact local validation implementation. Nitro acts on gas-phase molecular warm starts; qualified DFT energies, MeCN thermochemistry and candidate-admission evidence remain separate.

The [shared runtime launch contract](../../../environments/uma_nitro/runtime.json) sets the conda base `lib` directory in process-only `LD_LIBRARY_PATH`, supplying the required CXXABI symbol for ASE/sqlite. [Public API imports and the Nitro preset](import_probe.json) pass with that setting. Lambda2 advertises a CUDA12.4 driver, insufficient for this CUDA13 wheel build; the [probe notes](import_probe_notes.json) explicitly exclude GPU inference qualification there. The compatible target remains the H100 fleet, subject to actual numerical validation. This process setting does not modify the prefix, dependencies or original QM environment.
